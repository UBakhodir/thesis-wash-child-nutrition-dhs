## Citation processing: the rendering workflow this package assumes

All in-text citations use **pandoc Markdown citation syntax** referencing `bibliography.bib`:
- Parenthetical, one or more sources: `[@key]` or `[@key1; @key2]`, optionally with a locator: `[@key, p. 5]`.
- Narrative, author already named in the prose: `Author [-@key]` (suppresses the duplicate author name, renders only the year).
- No bare `@key` with no brackets and no suppression dash is used anywhere in this package; every citation was checked for this in `citation_map.md`.

**To render — two supported paths, with their actual current locations stated precisely (corrected in v12; see R16):**

1. **pandoc + citeproc** (recommended for a future generator producing Word or a different LaTeX structure from this one): run `pandoc` with `--citeproc`, passing `--bibliography=bibliography.bib` and a citation style file (`--csl=<style>.csl`). By default, pandoc-citeproc renders a reference list containing only the keys actually cited — the six uncited reserve entries in `bibliography.bib` do not need manual exclusion; do not add a `nocite: '@*'` metadata field. **Not verified in this environment**: pandoc is not installed here (`which pandoc` / `Get-Command pandoc` both fail), so this path is documented but untested by this project; a future session with pandoc available should verify it before relying on it.
2. **xelatex + biblatex/biber**, consistent with the university guidelines' own named toolchain for Chicago-style references ("available in Zotero and BibLaTeX"): a converter, `md2tex.py`, and supporting templates (`preamble.tex`, `titlepage.tex`, `declaration.tex`) exist under `../v3_2026-10-07/build/` through `../v6_2026-10-07/build/` (each version's own copy, evolving across those four passes) — there is **no `build/` directory under this version (`v12_2026-10-10/`), nor under v7 through v11**. The v6 build is the most recent and most thoroughly verified of the four (32-page main text, 0 LaTeX errors), so it is the one referenced specifically below, not because it is the only one that exists. Every one of v3–v6's own generated chapter `.tex` files and `main.pdf` reflects that specific version's prose, not v7 through v12's corrections (including every correction in this pass); none must be reused as if it contained current text. A future build of this canonical v12 source must: (a) copy or point the converter/template files from `../v6_2026-10-07/build/` (the most up-to-date of the four) to a **new** output location (e.g. a fresh `build/` under this version, not reusing any prior version's own generated `chapters/`/`appendices/` `.tex` output), (b) regenerate every chapter `.tex` file freshly from this version's own `.md` files via `md2tex.py`, and (c) include an explicit source-version check (e.g. recording this file's own header version string, or a hash of the canonical `.md` files, in the build log) so a reader of the resulting PDF's build log can confirm which manuscript version it was actually built from. **No such build has been run for v12** (or for v7 through v11); this is documented as the build procedure a future pass should follow, not as a claim that it has already happened.

By default, biblatex also renders a reference list containing only the keys actually cited in the document (confirmed by inspection of the v6 diagnostic build). **These are visible Markdown captions only, not automatic LaTeX captions or cross-reference labels, and the two must not be conflated.** The bold `**Table 5.N — ...**` lines are static text in the `.md` source: a future conversion will carry them through as plain bold text, exactly as written, unless the converter is specifically modified to recognise and transform them. `../v6_2026-10-07/build/md2tex.py`'s `convert_table()` (confirmed directly from its source, lines ~137–174) does not parse, number, or cross-reference tables at all — it emits a bare `longtable` with rule lines and no `\caption{}` or `\label{}` call for any table, and nothing in this converter or in `CROSS_REFERENCE_MAP.md` (which resolves only "Section X.Y" prose references) gives these nine numbers any automatic linking, renumbering, or List-of-Tables behavior in a rendered PDF. A reader of this canonical source sees nine correctly numbered captions; a future xelatex build using the current, unmodified v6 converter would render them as nine bold text lines with no `\caption`/`\label`/List-of-Tables support and no protection against the numbers silently going stale if a table is later added, removed, or reordered. Implementing true automatic LaTeX captions/labels (parsing each `**Table N.M — ...**` line and emitting `\caption{...}\label{tab:N.M}`, with in-text `Table~\ref{tab:N.M}` replacing the three existing hard-coded "Table 5.1"/"Table 5.3" prose mentions) is left for whichever future pass actually regenerates `md2tex.py` fresh from `../v6_2026-10-07/build/` for a new build (per "Citation processing" above); the frozen v6 copy itself is not edited here, consistent with every other version in this package being preserved unmodified, and no PDF was built or re-rendered to check how these captions actually typeset.
