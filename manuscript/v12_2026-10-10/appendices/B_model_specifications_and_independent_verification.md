## B.2 Independent verification of the pooled historical model (Section 4.6, Section 5.6)

This thesis's own pipeline (`scripts/historical_wash/16_estimate_preliminary.py`) estimates all 291 historical models using a hand-written weighted within-cluster demeaning estimator. A prior independent check (`scripts/historical_wash/17_validate_estimates.py`) re-estimated four representative *country-specific* cells (Ghana water HAZ weighted and unweighted; Ghana sanitation WAZ; Nigeria sanitation HAZ) with an explicit-dummy-variable statsmodels implementation, matching to 3×10⁻¹⁴.

This did not cover the pooled, multi-country model, which is the headline result of the historical extension. `scripts/historical_wash/20_validate_pooled_estimate.py`, written for this manuscript-preparation phase of the project, independently:

1. Rebuilds the estimation sample from the analysis-candidates stage directly (not from the stored, already-estimated model dataset), applying every filtering step explicitly and logging row counts (reproduced in Appendix A.3).
2. Estimates with `linearmodels.PanelOLS` — a different software library from the project's own hand-written estimator — using entity (cluster) fixed effects and clustered CRV1 standard errors.
3. Reports both the PRIMARY (`auto_df=True`) and FULL\_DUMMY\_DF (`auto_df=False`) conventions.
4. Estimates the unweighted counterpart on exactly the same final observations.

**First attempt and its correction, reported for transparency.** An initial run of this independent script used a single pooled reference birth-year cell (rather than a separate reference year per country) and omitted the child's own age-in-months as a linear control. This produced β per 10 points = 1.385 against the stored 1.026 — a roughly 35% discrepancy — despite the sample size (N=23,018), cluster count (G=3,114), and exposure mean/SD matching the stored values exactly, which is what indicated a specification difference rather than a sample-construction error. After matching the documented design exactly (country-local-reference birth-year dummies; child age-in-months included), the independent estimate converged to:

**Which of the two changes actually explains the 1.385-vs-1.026 gap (2026-10-09 diagnostic, not speculation).** Because both changes were made at once in the original attempt, and that attempt's exact code was never committed to this repository, this gap could not originally be decomposed. A dedicated diagnostic (`scripts/historical_wash/25_diagnose_birthyear_coding_and_age_control.py`) isolates them on a faithful reconstruction of the described design, comparing the two birth-year schemes on the actual transformed design the estimator uses — the weighted within-cluster-demeaned matrix, not the raw one — because raw-space comparisons alone cannot establish whether a fitted coefficient must be unaffected. **The exposure variable (E10) is never used to construct any of the comparisons below**: an earlier version of this diagnostic residualized the birth-year blocks against a set that included E10 itself before comparing ranks, which is circular (residualizing against E10 can remove exactly the part of a block that would otherwise be shown to affect E10's own coefficient); the corrected version below keeps E10 entirely separate from every column-space comparison and instead verifies directly that E10's own residual values are unaffected by the choice of scheme.

*Raw design matrix.* The single-pooled-reference birth-year scheme does change the raw design matrix: 13 birth-year dummy columns vs. the country-local scheme's 12, because Nigeria's own observed birth-year range (2013–2017) does not include the single global reference year (2009, the earliest birth year observed anywhere in the pooled sample), so Nigeria keeps a dummy for its own earliest year that the country-local scheme drops as its reference category. This extra column survives the cluster-fixed-effect demeaning step on its own (it is not itself absorbed).

*Step 1 — direct comparison, before touching E10 or any other covariate.* Demeaning each scheme's birth-year block (weighted within-cluster demeaning, the identical transformation `PanelOLS`'s entity effects use) and comparing the two blocks' ranks directly: local = 12 (of 12 surviving columns), pooled-single-reference = 12 (of 13 surviving columns — one is already redundant at this stage), combined = 12. The two demeaned blocks already span **equal** subspaces before any residualization is performed.

*Step 2 — residualized against the shared nuisance controls only (age-in-months, maternal age, demographic dummies), E10 explicitly excluded from this projection, checked separately with and without age-in-months.* Equal span confirmed in both cases (rank 12/12/12 throughout).

*Step 3 — E10's own residual, compared directly.* Building each scheme's complete nuisance specification (the absorbed cluster fixed effect, plus the shared controls, plus that scheme's own birth-year block) and residualizing E10 against each: the two resulting weighted residual-exposure vectors differ by a maximum of 1.73×10⁻¹⁵ in absolute terms (relative to the vector's own norm, 2.23×10⁻¹⁶) — the same vector, not merely a similar one, confirmed elementwise rather than inferred from rank alone.

*Step 4 — independent cross-check via the explicit weighted Frisch–Waugh–Lovell formula*, β = (e′Wỹ)/(e′We), computed from first principles rather than read off `PanelOLS`'s internal output: this independently computed β matches `PanelOLS`'s own fitted coefficient to within 4.4×10⁻¹⁶ across all four scheme/age-control combinations.

*Step 5 — mechanical explanation of the redundant column, without reference to E10.* Nigeria's full set of five own-year dummy columns in the pooled-single-reference scheme sums, exactly (confirmed elementwise across all 23,018 observations), to Nigeria's own raw country indicator; that indicator demeans to exactly 0.0, because every DHS cluster belongs to exactly one country, so a column that is constant within every cluster is trivially absorbed by the cluster fixed effect. This is the specific mechanism behind the equal-span result above, not an unexplained coincidence.

Taken together, Steps 1–3 establish — directly, not merely by inference from one rank comparison — that the two birth-year schemes are equivalent nuisance specifications for the exposure coefficient; Step 4 independently confirms the resulting coefficient via a from-scratch computation; Step 5 explains the mechanism. The fitted values confirm the exposure coefficient is identical between schemes at floating-point precision: 1.0255530672006674 (local) vs. 1.0255530672006667 (pooled-single-reference), an absolute difference of 6.661338147750939×10⁻¹⁶ (holding the age-in-months control fixed), and 1.3852855197991372 vs. 1.3852855197991374 (absolute difference 2.220446049250313×10⁻¹⁶) holding it excluded — both differences at the level of floating-point machine epsilon, not an approximation, and reported here as independently observed numerical evidence consistent with the algebraic result, not merely inferred from it.

The age-in-months control, in contrast, fully accounts for the gap on its own: 1.0255530672006674 with it included vs. 1.3852855197991372 without it — the former matches the stored value (1.025553) and the latter approximately reproduces the documented early-attempt value ("1.385") on this reconstruction, under *either* birth-year scheme. This is evidence, on this reconstruction, that the age-in-months omission explains the historical 1.385-vs-1.026 gap, and that the birth-year reference-coding choice — though it genuinely does change the raw design matrix, and this is not dismissed as a non-issue — does not affect the fitted exposure coefficient, because the two schemes carry equal information after cluster-FE absorption. Stated as this diagnostic's finding on a faithful reconstruction, with full numerical tolerances and the complete five-step evidence chain reported in its own execution log (`data/processed/estimation/birthyear_coding_diagnostic_20261009T081301Z/`, RESTRICTED), not as certainty about the specific, unpreserved original code, and not as exact recovery of its reported output.

**The SE difference above is fully explained, not residual numerical noise.** `16_estimate_preliminary.py`'s declared small-sample correction is `(G/(G-1)) × ((N-1)/(N-K))` applied to the raw cluster-robust sandwich, with CIs/p-values from a Student's *t* distribution on *G*−1 degrees of freedom (read directly from its source, lines 209–212). `20_validate_pooled_estimate.py`'s and `21_validate_all_primary_cells.py`'s **original, incomplete** `PanelOLS.fit(cov_type="clustered", cluster_entity=True, auto_df=True)` call applied only *one* of the two factors the full correction requires: `auto_df=True` correctly sets the same-group, no-double-penalty degrees-of-freedom convention (confirmed by reading the installed `linearmodels` 7.0 source, `panel/model.py`'s `_determine_df_adjustment`), and `debiased=True` (the library's own default) applies an `N/(N-K)` scale — but that original call did not also pass the *separate*, opt-in `group_debias=True` flag, so it never applied linearmodels' own `(G/(G-1)) × ((N-1)/N)` cluster-count adjustment (`shared/covariance.py`, `group_debias_coefficient`) at all. **After adding the missing `group_debias=True` flag**, the two factors the corrected call then applies together, `[N/(N-K)] × [(G/(G-1))×(N-1)/N]`, multiply out to something algebraically identical to `16`'s declared `(G/(G-1))×(N-1)/(N-K)` — so the missing flag, not a different formula and not floating-point noise, is the entire explanation for why the original, incomplete call's SE disagreed. `scripts/historical_wash/24_reconcile_inference_corrections.py` (new) re-fits all 24 primary cells with `group_debias=True` added: **every one of the 24 cells' SE now matches the stored value to the displayed precision (max remaining difference 0.0 at 8 decimal places)**, and a direct algebraic check (uncorrected sandwich SE × the manually computed combined scalar vs. the library's own corrected SE) confirms a zero residual for all 24 cells. Full detail and the per-cell table: `docs/provenance/independent_audit_v1_2026-10-07/09_update_2026-10-07_pass4.md`. This does not change the stored, authoritative SE in `16_estimate_preliminary.py`'s own output anywhere — that estimator's formula was correct throughout; what was corrected is the *validation* scripts' covariance configuration, not the pipeline being validated.

**What this verification establishes, and what it does not.** It establishes that the reported pooled coefficient and its standard error are computationally correct — the numbers the documented specification, correctly implemented in a second, independent library with an equivalent covariance configuration, actually produce. It does not establish that the specification identifies a causal effect, and it does not place this one cell in a higher *reporting* tier than its sibling historical models, all of which share the same unresolved documentation issues (Section 6; `docs/provenance/historical_wash_issue_register_v1_2026-10-07.md`).

## B.4 Estimator safeguard: the exposure-absorption and rank-deficiency defect, and its resolution (2026-10-10)

An external independent audit (`Independent_Thesis_Audit_2026-10-10.md`) identified a genuine code defect in `scripts/historical_wash/16_estimate_preliminary.py`'s `fit()` function. The function's absorbed-column filter dropped any column with zero within-cluster variation after weighted demeaning, but the exposure coefficient and its variance were then read by **fixed array position** (`beta[0]`, `V[0,0]`), not by the retained variable's name. If the exposure variable, $E$, happened to be absorbed by this filter — which the function's own earlier raw-standard-deviation check does not catch, because that check tests *raw* (between-cluster) variation, not *within-cluster* variation — the next retained column would silently occupy position 0 after the drop, and its coefficient would be reported as if it were $E$'s own. Separately, the function computed a design-matrix rank but never checked it against the number of retained columns before using a pseudoinverse to solve for coefficients, so a rank-deficient retained design (e.g. from an accidental exact collinearity between the exposure and a retained control) would silently return a minimum-norm pseudoinverse solution rather than flagging non-identifiability.

**Fix.** The function now (a) checks explicitly that `"E"` survives the absorbed-column filter and refuses to proceed (`status: "non_estimable_exposure_absorbed"`) if it does not, retrieving $E$'s coefficient and variance by its retained name/index rather than by position when it does survive; and (b) checks that the retained design matrix's rank equals its column count before computing coefficients, refusing (`status: "non_estimable_rank_deficient"`) rather than returning a pseudoinverse-based estimate if not. Neither change alters the computation for an already-estimable, full-rank case with $E$ retained: the ordinary path recovers the identical coefficient, standard error, and every other reported statistic, since $E$ is always constructed as the first design-matrix column and therefore still occupies position 0 whenever it is retained.

**Targeted tests**, tracked at `scripts/historical_wash/26_test_fit_safeguard.py` (synthetic data only; run against the actual patched function via direct import, not a reimplementation; re-run with `python 26_test_fit_safeguard.py` from that directory): (a) an ordinary estimable exposure (genuine between- and within-cluster variation) — estimates normally, recovering the simulated coefficient; (b) exposure varying between clusters but constant within each cluster — the exact failure mode described above — correctly refused as `non_estimable_exposure_absorbed`, with no `beta_per_point`/`se_CRV1`/`p_value` returned; (c) exposure made exactly collinear with a retained nuisance control after demeaning — correctly refused as `non_estimable_rank_deficient`; (d) a directly rank-deficient retained design via a duplicated dummy block — correctly refused as `non_estimable_rank_deficient`. All four tests pass.

**Verification that no published model was affected.** The patched script was re-run in full against the actual restricted inputs (`data/processed/analysis_samples/run_20261006T184744Z/`, `data/processed/child_exposure/run_20261006T183803Z/` — confirmed by SHA-256 to be bit-identical to the inputs used for the original, stored run), producing a fresh 291-model output written to a new timestamped directory (`data/processed/estimation/run_20261010T140944Z/`, RESTRICTED) without altering the original `run_20261006T185646Z/`. A dedicated, tracked comparison script, `scripts/historical_wash/27_compare_fit_safeguard_verification_run.py` (configurable `--original`/`--verification` paths; takes no hardcoded restricted path as a requirement), produced a public, machine-readable comparison summary: all 291 model IDs present in both runs with no duplicates; all six spec-identity fields (`family`, `product`, `outcome`, `sample_group`, `window`, `weighted`) matching for every row; both runs' `status` column reading `estimated` for all 291 rows; and, across the 15 numeric columns checked (coefficient, SE, both CI bounds, and p-value at both the per-point and per-10-point scale, plus `E_within_sd`, `E_residual_sd_after_controls`, `N`, `G_clusters`, `K_regressors`, `rank`) — this exact list, not an unenumerated "every column" — a maximum absolute difference of exactly 0.0 in every one. The two runs' output CSV files are in fact byte-for-byte identical (identical SHA-256 hash), a stronger result than the per-column check alone required. **2026-10-10, same-day correction**: the comparison script's own overall-success flag was found not to account for a value that is finite on one side and NaN/infinite on the other, nor for duplicate ids, missing required columns, or a NaN-vs-infinity difference — all now fixed and covered by synthetic regression tests (`scripts/historical_wash/28_test_compare_fit_safeguard_run.py`); re-running the corrected, stricter comparison against the same two real runs reaches the same conclusion (`docs/provenance/fit_safeguard_verification_comparison_v2_2026-10-10.json`; the original, pre-correction summary is preserved at `_v1_2026-10-10.json` for the record). This directly confirms, rather than merely infers from the earlier design-check evidence, that none of the 291 published historical models were affected by this defect: every one already had $E$ genuinely retained with full design-matrix rank.
