# Correction log: v5 → v6 (2026-10-07)

This pass responds to a direct instruction to correct three concrete problems found by inspecting commit `0090c16` and its committed v5 PDF. v5 is preserved unchanged; see `../v5_2026-10-07/` (a `POINTER_TO_V6.md` is added there). No empirical estimate changed.

## What changed

| Problem in v5 | Correction in v6 |
|---|---|
| **Real PDF table/text clipping.** `build/md2tex.py`'s table converter used unbounded `l` columns for every table; wide tables and long cells ran off the page, up to 1272pt (≈45cm) in Appendix A's variable-definitions table. The historical water/sanitation results tables (Results §5.6) crammed a coefficient, CI, *p*-value, and sample-size string into one unwrapped cell. | `convert_table()` now allocates explicit, content-proportional `p{}` wrapping widths within the actual text width; sample sizes/cluster counts moved out of coefficient cells into a separate table (verified identical between the water and sanitation tables for each outcome/country before merging them). Inline `\texttt{}` paths can now break at `/`, `_`, `.`, `-`. A second, independently-discovered bug (plain-prose `\_` double-escaping into visible `\textbackslash{}` text, e.g. "FULL\_DUMMY\_DF") was also fixed. Verified by **rendering pages to images and visually inspecting them** (`pymupdf`), not by warning counts — see `build/README.md` for the full before/after and which pages were checked. |
| **An unsupported "numerical noise" explanation for the historical-model SE/CI/p-value differences**, asserted in `docs/provenance/independent_audit_v1_2026-10-07/08_update_2026-10-07_pass3.md` without being demonstrated. | Read the installed `linearmodels` 7.0 source directly (`panel/model.py`, `panel/covariance.py`, `shared/covariance.py`). The independent validation scripts' `PanelOLS.fit(cov_type="clustered", cluster_entity=True, auto_df=True)` call omits a separate, opt-in `group_debias=True` flag that supplies part of the cluster-count small-sample correction the authoritative pipeline's hand-written formula applies. A new script, `scripts/historical_wash/24_reconcile_inference_corrections.py`, demonstrates this precisely: with `group_debias=True` added, all 24 primary cells' SE match the stored value to exactly 0.0 (8 decimal places), and a direct algebraic check confirms the two formulas are identical, not merely close. `appendices/B_model_specifications_and_independent_verification.md` §B.2 rewritten with the full derivation and result. |
| **Unsupported "unlikely to be a multiplicity artefact" claim**, Results §5.6 and Discussion §6.1: independent computational reproduction of a coefficient was conflated with evidence against it being one significant draw among many tested cells — properties that have nothing to do with each other absent an actual multiplicity correction, which this thesis does not apply anywhere. | Both sections rewritten to state plainly what the computational check does and does not establish: the number is correctly computed; this is not a multiplicity correction; no such correction has been applied; and this coefficient's chance of reflecting one significant draw among the cells tested has not been quantified or ruled out. |
