**Explanation of the small, non-zero differences** (required before relying on this as "matches," per this task's own instruction to explain any difference before changing any result): the coefficients themselves agree to floating-point noise (1e-14 to 1e-16, i.e., machine precision), confirming both implementations solve the identical weighted-demeaned normal equations. The SE/CI/p-value differences are one to three orders of magnitude larger than the coefficient differences because the CRV1 sandwich variance estimator involves squaring and summing per-cluster score contributions — a numerically less stable operation than the point estimate, so small differences in *how* each implementation performs the within-transformation (the project's own hand-rolled weighted group-demeaning via explicit matrix algebra in `16_estimate_preliminary.py`, vs. `linearmodels.PanelOLS`'s internal absorption via a different numerical routine, e.g. its own demeaning/QR path) compound further when forming the sandwich estimator, even though both apply the exact same documented `G/(G-1)*(N-1)/(N-K)` scalar correction on top. This is the expected signature of two different, correct numerical implementations of the same estimator — not a specification disagreement. No result, conclusion, or significance classification changes as a result.

### 2.2 Leave-one-out community WASH exposure, rebuilt from raw records (new this pass)

`scripts/dhs_harmonization/15_validate_loo_from_raw_records.py` (new, committed) independently rebuilds the LOO community water/sanitation exposure rate directly from the raw Ghana 2022 household recode (`data/raw/DHS/ghana/2022/HR/GHHR8CDT.zip`, member `GHHR8CFL.DTA`, read via `pandas.read_stata` — a different reader from the pipeline's own `pyreadstat.read_dta`), reimplementing the water/sanitation JMP classification from scratch (not importing `01_wash_mapping.py`) and a brute-force O(n²) per-cluster leave-one-out computation (not the pipeline's vectorized groupby/transform in `08_hr_cluster_wash_exposure.py`).

**Result after a caught-and-fixed bug in this new script** (see below): water matches perfectly (6,542/6,542 matched households, max abs diff 0.0000000000, 0 mismatches, perfect NaN-pattern agreement). Sanitation also now matches perfectly (6,542/6,542, max abs diff 0.0000000000, 0 mismatches, perfect NaN-pattern agreement) — output at `data/processed/loo_independent_validation_ghana.csv` (RESTRICTED, household-level, not committed).

**Bug found and fixed in the new validation script itself (not the pipeline)**: the first version of `15_validate_loo_from_raw_records.py`'s `brute_force_loo()` filtered excluded (non-classifiable) households with `vals[j] is not None`. The classification function returns a genuine Python `None` for excluded households, but once that `None` is stored in a pandas column that also holds `1.0`/`0.0` floats, pandas has no way to represent `None` in a `float64` Series and silently upcasts it to `NaN`. `float('nan') is not None` evaluates to `True`, so the filter failed to exclude these households from the "others" list; their `NaN` then propagated through `sum()`, making the whole leave-one-out rate `NaN` for any household whose cluster contained an excluded neighbour — even though enough genuinely classified neighbours existed. This produced exactly the symptom first observed: 1,537 of 6,542 Ghana households where the independent script reported `NaN` but the stored pipeline reported a valid rate, with no corresponding numeric mismatches on the households both methods *did* classify (because the bug only ever produces `NaN`, never a wrong non-`NaN` number) — a clean signature pointing at a bug in the new script rather than the authoritative pipeline. Water happened to match "perfectly" from the first run purely because Ghana's `hv201` (water source) column contains zero excluded (code 96/97) households, so the latent bug was never triggered for water — this was luck, not evidence the water check's logic was correct, and is noted here so it is not mistakenly cited as independent proof beyond what it actually showed at the time.

The fix: replace `vals[j] is not None` with `pd.notna(vals[j])`, which correctly catches both `None` and `NaN`. Re-run after the fix: perfect agreement on both water and sanitation, as reported above. **Diagnosed, before any authoritative result was touched**, per this task's explicit instruction — no file in `data/processed/pooled_kr_four_country_wash_exposure.parquet` or any downstream output was changed; the error was entirely contained in the new, not-yet-committed validation script.

As part of diagnosing this, the project's own sanitation classification spec (`01_wash_mapping.py`'s `SANITATION_CATEGORY_MAP_CORE`, `classify_sanitation_service()`, `SANITATION_SERVICE_COLLAPSE_MAP`) was read and exactly replicated independently (hv205 category → hv225-based service refinement for "Improved" rows only → Basic/Limited/NonImproved collapse) as part of ruling out a classification-logic explanation before finding the real cause. This confirmed the category/service/collapse logic itself was never the issue — in this Ghana 2022 file, no household's `hv225` (shared-facility) value ever took the value 7 among "Improved"-category rows, so the service-refinement step was a no-op here; the bug was purely a pandas `None`-vs-`NaN` plumbing issue in the new script.

## 3. Buffer-averaging independent validation (closed this pass)

Extends the data-layer check in `07_update_2026-10-07_pass2.md` §2 (which verified raster reading/coordinates/NoData but explicitly not the buffer-overlap averaging algorithm itself) with an independent numerical check of the buffer MEAN/valid-fraction *outputs*.

New script `scripts/historical_wash/23_validate_buffer_averaging_independent_mc.py` (committed; does not import or call anything from `10_spatial_extraction_v3.py`). Output at `data/processed/spatial_extraction/independent_mc_buffer_validation_20261007T181937Z/` (RESTRICTED-adjacent, aggregate-only — no coordinates or cluster identifiers — not committed).

**Method, independent of the primary script in multiple dimensions at once**: rejection sampling of points uniform in the disk (not the primary script's polar sampling, and not the same conceptual approach as its own internal `mc_reference()` self-check, which this script's author did not read before implementing); a closed-form WGS84 degrees-per-metre tangent-plane conversion (not `pyproj`'s AEQD projection the primary script uses); `rasterio` reading directly from the original downloaded archives (not the primary script's PIL/manual-TIFF-tag reading path); distinct RNG seed streams. The tangent-plane-vs-true-AEQD approximation error is ~4×10⁻⁷ relative at a 10 km radius (sub-centimetre) — negligible next to Monte Carlo sampling noise at the sample sizes used.

**Cases checked: 16**, 600,000 MC points each (≥ the 500,000-point target), across Ghana 2014, Kenya 2014, Nigeria 2018, both products:
- 6 full-coverage (3 urban/2km, 3 rural/5km)
- 6 partial/NoData-boundary (stored `valid_fraction` spanning 0.088–0.941)
- 4 zero-coverage (`valid_fraction==0`) — the only zero-coverage clusters in this dataset are 2 Kenyan clusters (one urban, one rural), constant across all 18 raster-years; no analogous zero-coverage cluster exists in Ghana or Nigeria in this data, so this case type is reported as Kenya-only rather than silently substituted with a different case type.

**Results**: across the 12 cases with a comparable mean, the largest standardised discrepancy is z=1.62 (Nigeria urban W_IMP: MC=95.3137 vs. stored 95.3131, diff 0.0005, MC SE 0.0003); mean |z|=0.77. Across all 16 valid-fraction comparisons, the largest is z=1.15 (Nigeria rural S_IMP boundary case: MC=0.60882 vs. stored 0.60954, diff 0.00072, MC SE 0.00063). All 4 zero-coverage cases: 0/600,000 MC-valid samples, exact match to stored `valid_fraction=0`. Zero cases with |z|>3 (the threshold that would flag a structural rather than sampling-noise discrepancy): 0 of 16 for either metric.

**Verdict**: the buffer-averaging (exact polygon-disk overlap) algorithm's output holds up fully under this independent check across full-coverage, partial/NoData-boundary, and zero-coverage cases, within justified Monte Carlo tolerance, using a genuinely different sampling scheme, projection approximation, RNG, and raster-reading path than the primary method. This closes workstream 3; combined with the pass-2 data-layer check, both halves of the spatial-extraction method the manuscript describes (reading the correct raster value, and averaging it correctly over the buffer) are now independently verified.
