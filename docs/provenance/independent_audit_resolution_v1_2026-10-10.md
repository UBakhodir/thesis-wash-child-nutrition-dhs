## R05 — Historical estimator can report another variable as the exposure when E is absorbed

**Status: confirmed as a genuine code defect; confirmed, by full re-estimation, that no published model was actually affected.** Read `fit()` in `16_estimate_preliminary.py` directly: the absorbed-column filter (line ~190, pre-fix) can drop `E` itself if it varies between clusters but is constant within each cluster (the earlier raw-SD check tests only *raw*, not within-cluster, variation), and the subsequent code read the exposure coefficient/variance by fixed position (`beta[0]`/`V[0,0]`), not by name — so if `E` were dropped, the next retained column's coefficient would be silently reported as `E`'s own. Separately, the design-matrix rank was computed but never checked against the retained column count before a pseudoinverse-based solve, so a rank-deficient retained design would silently return a minimum-norm estimate.

**Fix implemented**: `fit()` now (a) checks `"E"` is present in the retained column names after the absorption filter, returning `status: "non_estimable_exposure_absorbed"` if not, and (b) checks the retained design's rank equals its column count before solving, returning `status: "non_estimable_rank_deficient"` if not. Both checks preserve the exact existing computation for the already-estimable, full-rank case (E always occupies position 0 when retained, since it is always the first column constructed).

**Targeted tests**, tracked at `scripts/historical_wash/26_test_fit_safeguard.py` (synthetic data only — no restricted records, coordinates, or identifiers; run against the actual patched function via direct import, not a reimplementation; the module-level code in `16_estimate_preliminary.py` does no file I/O and only runs its full pipeline under `if __name__ == "__main__"`, so importing it via `importlib.util` with a different module name executes no restricted-data access — verified by running these tests with no restricted master-directory data required):
- (a) Ordinary estimable exposure (genuine between- and within-cluster variation): `status: estimated`, coefficient recovered close to the simulated true value (0.0520 vs. simulated 0.05).
- (b) Exposure constant within each cluster, varying only between clusters (the exact failure mode described): `status: non_estimable_exposure_absorbed`, no `beta_per_point`/`se_CRV1`/`p_value` returned. Before the fix, this configuration would have silently mislabeled another column's coefficient as E's own.
- (c) Exposure made exactly collinear with a retained nuisance control after demeaning: `status: non_estimable_rank_deficient`.
- (d) Directly rank-deficient retained design (duplicated dummy block): `status: non_estimable_rank_deficient`.
All four tests pass.

**Verification that no published model was affected**: re-ran `16_estimate_preliminary.py` in full, unmodified except for the fix, against the actual restricted inputs (`data/processed/analysis_samples/run_20261006T184744Z/`, `data/processed/child_exposure/run_20261006T183803Z/`; SHA-256-confirmed identical, before and after this run, to the hashes recorded in the original run's own manifest: `analysis: 06f6d98d...`, `construction: e095f48c...`). The new run wrote to a fresh timestamped directory (`data/processed/estimation/run_20261010T140944Z/`, RESTRICTED, `os.makedirs(..., exist_ok=False)` so it could not overwrite anything) without touching the original `run_20261006T185646Z/`. **2026-10-10, same-day follow-up**: this comparison is now a tracked, reproducible artifact rather than only a narrative claim — `scripts/historical_wash/27_compare_fit_safeguard_verification_run.py` (non-sensitive; configurable `--original`/`--verification` paths) produced `docs/provenance/fit_safeguard_verification_comparison_v1_2026-10-10.json`, which states its exact coverage explicitly: row-matched by model `id` (291 of 291 matched, 0 duplicates, 0 missing/extra on either side), all six spec-identity fields checked and matched, `status` checked and matched (`estimated` for all 291 rows in both runs), and exactly 15 named numeric columns checked (`beta_per_point`, `se_CRV1`, both CI bounds, `p_value`, `beta_per_10`, `se_per_10`, both per-10 CI bounds, `E_within_sd`, `E_residual_sd_after_controls`, `rank`, `K_regressors`, `N`, `G_clusters`) — **maximum absolute difference 0.0 in every one, and the two runs' CSV files are additionally byte-for-byte identical (same SHA-256 hash of the whole file)**, a stronger result than the per-column check alone requires. **This directly confirms — not merely infers from the earlier design-check evidence — that none of the 291 published historical models were affected by this defect.** This is a comparison of the original and patched versions of the same hand-written estimator against the same restricted inputs, not a claim that all 291 models were independently reproduced by a second estimation library — that separate, distinct validation (§B.2 above) covers only the 24 primary cells.

**2026-10-10, further same-day correction to this comparison script itself**: the script's own overall-success flag did not account for a finite-vs-NaN/infinite difference, a duplicated model id (a plain inner merge on a duplicate key fans out rather than failing), a missing required column (skipped rather than counted as a failure), or a NaN-vs-infinity difference specifically. All fixed — values are now classified into `finite`/`nan`/`+inf`/`-inf` with any mismatch between the two runs treated as a failure in its own right, the merge uses pandas' `validate="one_to_one"`, and every required column is checked present in both inputs before anything else runs. Seven synthetic regression tests (`scripts/historical_wash/28_test_compare_fit_safeguard_run.py`) prove each failure mode is now caught and that unchanged input still passes. Re-run against the same two real runs under the corrected, strictly-gated comparison: `docs/provenance/fit_safeguard_verification_comparison_v2_2026-10-10.json` reaches the identical conclusion (`identical_within_stated_tolerance: true`; the two CSVs remain byte-identical; 0 failure reasons across every newly-added check). The original, pre-correction summary is preserved unchanged at `_v1_2026-10-10.json`.

**Changed**: `scripts/historical_wash/16_estimate_preliminary.py` (code fix, preserving all existing output for estimable cases); `appendices/B_model_specifications_and_independent_verification.md` (new §B.4 documenting the fix and the all-291-model verification). No published coefficient, SE, CI, p-value, N, or G changed. **Limitation**: the fix changes behaviour only for configurations that were never actually observed in this project's 291 registered models; it has not been exercised against any hypothetical future model specification, and the four synthetic tests, while covering the specific failure modes described, are not an exhaustive test of every possible non-estimable configuration.
